# الخطة الأمنية الشاملة — منصة الاتصالات الإدارية

**مبدأ الخطة:** كل بند إما (أ) **قائم** في المنصة اليوم، أو (ب) **إعداد/تشغيل** خارج الكود (شبكة، سياسات)، أو (ج) **تحسين برمجي إضافي** يُضاف عبر وحدة ملحقة ومفتاح إعداد افتراضه «مُعطَّل/متوافق»، فلا يتعارض مع أي ميزة سابقة ولا يُلزم أحدًا بتغيير سلوكه إلا بقرار المدير. كل تحسين برمجي يُرفق باختبار، ويجب أن تبقى الاختبارات الحالية (70) ناجحة.

> الحالة المذكورة «قائم» مأخوذة من الكود الحالي. أما أرقام الموارد والمدد فهي تقديرات تخطيطية تُراجع مع فريق التقنية.

## 1) تحليل التهديد ونموذج المخاطر

### الأصول (مصنّفة)
| الفئة | الأصل | الحساسية | الأثر عند الاختراق |
|---|---|---|---|
| A (حرجة) | المراسلات «سري/سري للغاية» ومرفقاتها | عالية جدًا | تسرّب معلومات، ضرر سيادي/سمعة |
| A | قاعدة البيانات `acp.db` وسجل التدقيق | عالية | فقدان السلامة والمساءلة |
| A | مفاتيح: `ACP_ENC_KEY`، مفتاح التوقيع، مفاتيح API/JWT | عالية | فك التشفير، تزوير التواقيع والجلسات |
| B (عالية) | حسابات المدير وكبار الموظفين، أسرار TOTP | عالية | تصعيد صلاحيات |
| B | النسخ الاحتياطية (محلية/بديلة/باردة) | عالية | تسرّب شامل |
| C (متوسطة) | بيانات الموظفين والوحدات، الإعدادات، القوالب | متوسطة | هندسة اجتماعية |
| D (عامة) | الشعار والاسم والألوان (نقاط `public/*`) | منخفضة | لا شيء يُذكر |

### الجهات المهدِّدة وأساليبها
| الجهة | الدافع | أساليب محتملة | الضوابط الرئيسة |
|---|---|---|---|
| مهاجم خارجي انتهازي | ابتزاز/بيع بيانات | تخمين كلمات مرور، استغلال ثغرات معروفة، تصيّد | MFA، قفل الحساب، WAF، تحديثات |
| جهة منظَّمة/دولة (APT) | تجسس | تصيّد موجَّه، سلسلة توريد، استغلال يوم الصفر، حركة جانبية | Zero Trust، تقسيم الشبكة، EDR/SIEM، تشفير |
| موظف داخلي ساخط/مهمل | انتقام/إهمال | تصفح غير مصرّح، تصدير جماعي، حذف، مشاركة روابط | RBAC/ABAC، تسجيل المشاهدة والرفض، كشف الانحراف، سجل غير قابل للتعديل |
| مورد/مقاول | وصول مفوَّض | حساب مشترك، مكتبة ملوَّثة | وصول مؤقت، SBOM، اتفاقيات أمنية |
| برمجيات خبيثة/فدية | مالي | تشفير الخوادم والنسخ | نسخ غير قابلة للتعديل/معزولة، تجزئة |

### أبرز سيناريوهات الهجوم (STRIDE مختصر)
1. **انتحال هوية** (S): سرقة رمز الجلسة عبر XSS ← CSP صارم + `textContent` فقط + جلسات قصيرة. 
2. **تلاعب** (T): تعديل سجل التدقيق ← محفوظ بمحفِّزات DB + سلسلة تجزئة؛ يبقى خطر «مدير الخادم/القاعدة» ← خارجية السجل (SIEM/WORM).
3. **إنكار** (R): إنكار اعتماد خطاب ← توقيع إلكتروني HMAC + QR تحقق.
4. **تسرّب** (I): تصدير أو مرفق غير مصرّح ← تصنيف + تصريح + ABAC صارم + تشفير المرفقات.
5. **حجب خدمة** (D): إغراق تسجيل الدخول/البحث ← حدود معدّل + WAF.
6. **رفع صلاحيات** (E): ثغرة مسار/حقن ← استعلامات معلَّمة، فحص الأدوار على الخادم.

## 2) إدارة الهوية والوصول (IAM)

| الضابط | الحالة | الإجراء |
|---|---|---|
| تجزئة كلمات المرور | **قائم** PBKDF2-SHA256 بملح | رفع عدد التكرارات دوريًا؛ دراسة Argon2 إن توفرت مكتبة مُعتمدة |
| قفل الحساب بعد محاولات فاشلة | **قائم** (15 دقيقة) | إضافة حد معدّل على IP + تنبيه عند قفل حسابات مدير |
| انتهاء الجلسة | **قائم** (8 ساعات) | إضافة «انتهاء خمول» (مثلاً 30 د) كخيار إعداد |
| MFA (TOTP + رموز استرداد) | **قائم** وقابل للإلزام حسب الأدوار | **إلزام MFA لـ admin/manager فورًا**؛ لاحقًا WebAuthn/FIDO2 (مفاتيح أمان) لمقاومة التصيّد |
| SSO | **قائم** عبر ترويسة وسيط موثوق | اعتماد OIDC/SAML عبر وسيط (Keycloak/Entra/ADFS) أمام المنصة مع حصر الشبكة بالوسيط فقط |
| RBAC | **قائم** + `role_perms` | مراجعة ربع سنوية للأدوار (إعادة اعتماد الصلاحيات) |
| أدنى صلاحية + مستويات سرية | **قائم** (clearance، ABAC صارم، مسودات مخفية) | تفعيل `abac_strict_secret` في الإنتاج |
| سياسة كلمة المرور | **جزئي** | إضافة حد أدنى للطول (14) وقائمة كلمات شائعة محظورة ومنع إعادة الاستخدام (إعداد افتراضه الحالي) |
| حسابات الخدمة | **قائم** (OAuth client-credentials/JWT) | نطاقات (scopes) أضيق، انتهاء مفتاح، تدوير 90 يومًا |
| حسابات مدير الطوارئ | غير قائم | حساب Break-glass بكلمة طويلة محفوظة في خزنة، تنبيه فوري عند استخدامه |

## 3) التشفير وإدارة المفاتيح

| الطبقة | الحالة | الإجراء |
|---|---|---|
| نقل | **قائم** (HTTPS مباشر ويُلزَم TLS1.3 بـ`ACP_TLS_MIN`) | **التشغيل خلف وكيل عكسي TLS 1.3** (Nginx/Envoy) + HSTS + OCSP stapling؛ إضافة ترويسة HSTS من المنصة (إعداد) |
| مخزّن (مرفقات) | **قائم** Fernet (AES-128-CBC+HMAC) عبر `ACP_ENC_KEY`؛ **مغلق عند الفشل** | الانتقال لتشفير AES-256-GCM للمرفقات الجديدة (ترقية مع إبقاء قراءة القديم) |
| قاعدة البيانات | غير مشفّرة على مستوى الملف | تشفير القرص/الحجم (BitLocker/LUKS) كحدّ أدنى؛ SQLCipher عند الحاجة |
| النسخ الاحتياطية | **قائم** مع بصمات تحقق + نسخة بديلة + باردة | تشفير الأرشيف قبل النسخ البديل، مفتاح منفصل |
| إدارة المفاتيح | مفاتيح في متغيرات بيئة | نقلها إلى **خزنة أسرار** (Vault/Azure Key Vault/AWS KMS) وحقنها وقت التشغيل؛ فصل مفتاح التشفير عن مفتاح التوقيع |
| دوران المفاتيح | غير مؤتمت | دوران سنوي لمفتاح التشفير بمعرّف إصدار للمفتاح (key id) ليبقى فك المرفقات القديمة؛ دوران مفتاح التوقيع بقبول القديم للتحقق فقط |
| HSM | – | اختياري للمفتاح الجذري (Cloud HSM/ جهاز محلي) عند متطلبات سيادية |

## 4) الأمن الشبكي والبنية التحتية

**مخطط معماري أمني (مستويات):**

```
 الإنترنت/الشبكة الداخلية
        │
 [جدار ناري NGFW + IPS]  ← IDS/IPS، حجب جغرافي، حدود معدّل
        │
 [WAF + وكيل عكسي TLS1.3]  ← OWASP CRS، HSTS، حجم طلب، ترويسات
        │  (DMZ)
 ───────┼────────────────────────────────────────────
        │   شبكة التطبيقات (Segment B)
 [منصة الاتصالات: عملية بلا صلاحيات جذر، منفذ داخلي فقط]
        │        │               │
        │        │               └─► [SIEM/Syslog WORM]  (سجلات + تنبيهات)
        │        └─► [خزنة الأسرار/KMS]
 ───────┼────────────────────────────────────────────
        │   شبكة البيانات (Segment C — لا وصول مباشر من المستخدمين)
 [قرص مشفّر: acp.db + uploads]   [نسخ احتياطية غير قابلة للتعديل/معزولة]
        │
 [إدارة: VPN + MFA + محطة قفز (Bastion)]  ← الوصول الإداري الوحيد
```

| الضابط | الإجراء |
|---|---|
| التقسيم | ثلاث شبكات على الأقل (DMZ / تطبيق / بيانات) وقواعد «رفض افتراضي» |
| WAF/IPS | قواعد OWASP CRS؛ وضع المراقبة أسبوعين ثم الحجب |
| NAC و802.1X | لأجهزة الموظفين المتصلة بالمنصة داخليًا |
| VPN | WireGuard/IPsec بـ MFA للوصول عن بُعد؛ لا تعرّض منفذ المنصة للإنترنت مباشرة |
| Zero Trust | التحقق عند كل طلب: هوية + حالة الجهاز + سياق؛ المنصة تدعم ذلك جزئيًا عبر ABAC وسجل عناوين IP |
| تقوية الخادم | حساب خدمة بلا صلاحيات، قفل أذونات `data/` (قراءة للخدمة فقط)، إغلاق المنافذ، تحديثات OS آلية |

## 5) أمان التطبيق ودورة التطوير (SDLC)

| الخطر | الحالة الحالية | التحسين |
|---|---|---|
| SQLi | **قائم**: استعلامات معلَّمة | اختبار آلي يبحث عن تركيب نصوص SQL (SAST) |
| XSS | **قائم**: بناء DOM بـ`textContent` فقط + CSP `default-src 'self'` بلا `unsafe-inline` | إبقاء القاعدة «لا innerHTML» بقاعدة فحص في CI |
| CSRF | الرمز في ترويسة `Authorization` (لا كوكيز) فلا ينطبق عادةً | إن أُضيفت كوكيز مستقبلًا: `HttpOnly; Secure; SameSite=Strict` + رمز CSRF |
| الجلسات | رمز مخزّن في sessionStorage (يزول بإغلاق التبويب) | خيار كوكي `HttpOnly` عبر الوكيل لتقليل أثر XSS؛ إبطال الجلسات عند تغيير كلمة المرور |
| ترويسات الأمان | **قائم**: CSP, nosniff, X-Frame-Options, Referrer-Policy | إضافة HSTS وPermissions-Policy وCOOP/CORP |
| رفع الملفات | حدّ حجم + اسم مُنظَّف + تخزين باسم عشوائي؛ الشعار يُفحص بالتوقيع | فحص برمجيات خبيثة (ClamAV) على المرفقات، قائمة أنواع مسموحة قابلة للضبط |
| حدّ المعدّل | قفل الحساب فقط | حد معدّل لكل IP/رمز على الدخول والبحث والتصدير |
| الأسرار في الكود | لا أسرار ثابتة | فحص أسرار (gitleaks) في CI |

**خط CI/CD الموصى به:** مراجعة كود إلزامية (شخصان للتغييرات الأمنية) ← `ruff/bandit` (SAST بايثون) ← `gitleaks` ← `pip-audit` ← الاختبارات (70) ← بناء ← **DAST** (OWASP ZAP ضد بيئة اختبار) ← نشر. تُحمى فرع `main` من الدفع المباشر.

## 6) المراقبة والتدقيق

| العنصر | الحالة | الإجراء |
|---|---|---|
| سجل تدقيق غير قابل للتعديل | **قائم**: محفِّزات تمنع UPDATE/DELETE + سلسلة تجزئة | تصدير مستمر إلى SIEM/WORM (خارج صلاحية مدير الخادم) |
| تسجيل المشاهدة والرفض | **قائم** | إدراجها في قواعد SIEM |
| كشف الانحراف | **قائم** (anomaly σ) | ربط تنبيهاته بقناة الحوادث |
| SIEM | غير قائم | Wazuh/Elastic أو الحل المؤسسي؛ استقبال Syslog + سجلات الوكيل والنظام |
| تنبيهات حرجة | – | فشل دخول متكرر، قفل حساب مدير، تصدير كبير، استعادة نسخة، تعديل إعدادات أمنية، استخدام Break-glass، فشل التحقق من سلسلة التجزئة |
| الاحتفاظ بالسجلات | – | سجل التطبيق ≥ 12 شهرًا (ساخن 3 + بارد 9)، سجلات الأمن 24 شهرًا أو حسب الجهة المنظِّمة |
| فحص دوري للسلسلة | – | مهمة يومية تتحقق من سلامة سلسلة التجزئة وتنبّه |

## 7) النسخ الاحتياطي واستمرارية العمل

| العنصر | الحالة | الإجراء |
|---|---|---|
| نسخ دورية + بصمات | **قائم** | RPO مستهدف ≤ 4 ساعات (`ACP_BACKUP_HOURS`) |

| اختبار الاستعادة | يدوي | **اختبار استعادة فصلي موثّق** على بيئة منفصلة مع قياس RTO (هدف ≤ 4 ساعات) |
| التعافي من الكوارث | – | موقع تعافٍ ثانٍ دافئ، دليل تشغيل (Runbook) مُجرَّب، قائمة الاعتماديات (DNS، شهادات، مفاتيح) |

| النشاط | الدورية |

| DAST آلي (ZAP) | مع كل إصدار |

## 9) الامتثال والحوكمة

| الإطار | الربط بالمنصة |
|---|---|
| **المحلي (السعودية)**: ضوابط الأمن السيبراني الأساسية ECC وضوابط الأمن السيبراني للبيانات DCC، ونظام حماية البيانات الشخصية PDPL، وضوابط هيئة الحكومة الرقمية | الاحتفاظ والإتلاف بلجنة، تصنيف البيانات، سجل التدقيق، الإقامة المحلية للبيانات |
| **ISO/IEC 27001:2022** | ملحق A: التحكم بالوصول (A.5/8)، التشفير (A.8.24)، السجلات (A.8.15)، النسخ (A.8.13)، الموردون (A.5.19–22) |
| **GDPR** (إن انطبق) | الحد الأدنى من البيانات، حق الوصول/المحو (مع استثناء الاحتفاظ النظامي)، إخطار الخرق خلال 72 ساعة |

**الوثائق المطلوبة:** سياسة أمن المعلومات، سياسة التحكم بالوصول، التصنيف والتعامل مع البيانات، سياسة التشفير، النسخ والتعافي، الاستجابة للحوادث، إدارة الثغرات والتغيير، سجل المخاطر، بيان قابلية التطبيق (SoA). تُراجع سنويًا وتُعتمد من لجنة الأمن.

## 10) الطرف الثالث وسلسلة التوريد

- **مزايا قائمة:** المنصة بلا اعتماديات خارجية إلزامية (مكتبة بايثون القياسية) ولا CDN؛ مكتبة `cryptography` اختيارية فقط ← سطح هجوم صغير جدًا.
- **الإجراءات:** قائمة مكونات (SBOM) بصيغة CycloneDX؛ تثبيت الإصدارات بتجزئات (`pip --require-hashes`)؛ `pip-audit` أسبوعيًا؛ تحديث نسخة Python الأمنية شهريًا.
- **الموردون** (بريد/SMS/استضافة/السحابة): استبيان أمني، شهادة ISO 27001 أو ما يعادلها، بند إخطار بالحوادث خلال 24–72 ساعة، حق التدقيق، إقامة البيانات، خروج آمن (إرجاع/إتلاف البيانات)، مراجعة سنوية.
- **حسابات الموردين:** مؤقتة، بأدنى صلاحية، بمشرف داخلي، وتُسجَّل جلساتها.

الإجراء البشري: «لا تعرف؟ أبلغ، لا تنقر». لا عقوبة على الإبلاغ الصادق.

## ضمان عدم التعارض مع المزايا الحالية
1. كل تحسين برمجي = وحدة/إعداد إضافي بقيمة افتراضية متوافقة (مثل المصادقة الثنائية: تُلزَم بقرار المدير فقط).
2. لا تغيير في بنية الجداول إلا بإضافة أعمدة (آلية `MIGRATIONS` القائمة).
3. تُنفَّذ كل مرحلة بفرع مستقل، وتُدمج بعد نجاح الاختبارات الحالية والجديدة معًا.
4. التراجع ممكن بإيقاف المفتاح المعني دون استرجاع قاعدة البيانات.
